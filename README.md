# NOL 예매 버튼 감시

인터파크 예매 대기 화면과 [SSG 티켓](https://ticket.ssg.com/ticket)에서 예매 버튼이 정상적으로 활성화되면 한 번 클릭하는 크롬·엣지 확장 프로그램입니다. [티켓팅 연습 사이트](https://ticket.ggul.store/)에서도 같은 방식으로 시험할 수 있습니다. 이미 열린 예매 탭에서 사용합니다. 좌석 선택이나 결제는 처리하지 않습니다.

## 설치

1. 크롬에서는 `chrome://extensions`, 엣지에서는 `edge://extensions`를 엽니다.
2. **개발자 모드**를 켜고 **압축해제된 확장 프로그램을 로드합니다**를 선택합니다.
3. 이 폴더 안의 `extension` 폴더를 선택합니다.

배포 ZIP으로 설치한다면 먼저 압축을 푼 뒤, `manifest.json`이 바로 들어 있는 폴더를 선택합니다. ZIP 안의 `INSTALL.md`에도 설치와 연습 방법이 있습니다.

## 사용

1. 사이트에서 로그인한 뒤 예매 화면을 정상적인 경로로 엽니다. 인터파크는 `https://tickets.interpark.com/gates/ticket/숫자` 형식, SSG는 `https://ticket.ssg.com/ticket` 또는 `/ticket/` 화면을 지원합니다. 쿼리와 해시가 붙은 주소도 사용할 수 있습니다.
2. 확장 프로그램 아이콘을 열어 공연명, 버튼 문구, 상태를 확인합니다.
3. **감시 시작**을 누릅니다. `남은시간 02:45`처럼 카운트다운이 표시되는 동안에도 감시를 시작할 수 있습니다. 카운트다운이 끝나고 **예매하기** 버튼이 활성화되면 한 번 클릭합니다. 예매 버튼이 이미 활성화되어 있다면 즉시 한 번 클릭합니다.
4. 감시가 시작되면 팝업을 닫아도 해당 페이지에서 계속 작동합니다. **감시 중지**를 누르려면 팝업을 다시 엽니다.
5. 새로고침하거나 다른 페이지로 이동하면 감시가 끝납니다. 다시 감시하려면 확장 프로그램에서 직접 **감시 시작**을 누릅니다.

버튼을 클릭하면 상태는 **클릭 실행**으로 바뀌고 최근 감지 시각, 클릭 호출 시각, 두 시점 사이의 지연이 팝업에 표시됩니다. 이는 예매 성공을 뜻하지 않습니다. 사이트가 자동 클릭을 받지 않거나 다음 화면을 차단할 수 있습니다.

업데이트 후에는 확장 프로그램 관리 화면에서 확장 프로그램을 **새로고침**하고, 기존 예매 대기 탭도 새로고침하거나 정상 경로로 다시 연 뒤 **감시 시작**을 누릅니다. 이미 열린 탭에는 이전 코드가 남아 있을 수 있습니다.

v1.2.1부터 NOL(인터파크)은 안내 제목에 관계없이 지원 URL과 버튼으로 예매 대기 화면을 판단합니다. ‘예매는 오픈 시간부터 가능해요’가 표시되거나 제목이 없어도 카운트다운 버튼을 감시할 수 있습니다. 접근 오류가 없고 카운트다운·예매 버튼 후보가 정확히 하나일 때 시작할 수 있으며, 카운트다운이 `00:00`이 되어도 **예매하기**로 바뀌고 활성화될 때까지 클릭하지 않습니다.

## SSG 티켓에서 사용

1. [SSG 티켓](https://ticket.ssg.com/ticket)의 경기 목록 화면에서 확장 프로그램을 엽니다. 준비 안내 제목은 필요하지 않습니다.
2. `10.14(수) 11:00 오픈 예정` 또는 `남은시간 02:45`가 표시되는 동안 **감시 시작**을 누릅니다. 버튼 안의 문구가 중첩된 요소에 있어도 감시합니다.
3. 문구가 **예매하기** 또는 **예매**로 바뀌고 버튼이 활성화되는 순간 추가 대기 없이 한 번 클릭합니다. 이미 활성화된 예매 버튼은 시작 즉시 클릭합니다.

오픈 예정 안내나 `남은시간 00:00` 자체는 클릭하지 않습니다. 안내 시각 도달만으로 클릭하지 않으며, 매진·마감 또는 다른 문구는 대기합니다. 화면에 보이지 않거나 비활성화된 버튼도 클릭하지 않습니다.

오픈 예정·카운트다운·예매 버튼을 합쳐 후보가 하나일 때만 시작할 수 있습니다. 후보가 여러 개면 시작할 수 없고, 감시 중 후보가 추가되면 중지합니다. 사용자가 대상 버튼을 직접 클릭해도 감시가 끝납니다.

현재 SSG 지원은 실제 `button`이 **예매하기** 또는 **예매**로 전환되는 화면을 대상으로 합니다. 다른 문구나 링크 형태로 전환되면 클릭하지 않습니다. 실제 서비스의 예매 진입 성공은 모의 테스트만으로 확인할 수 없습니다.

## 연습 사이트에서 시험

1. 확장 프로그램을 이미 설치했다면 `chrome://extensions` 또는 `edge://extensions`에서 **새로고침**을 눌러 이번 변경을 반영합니다.
2. [ticket.ggul.store](https://ticket.ggul.store/)를 열고, 준비 시간이 필요하면 **10초**를 선택합니다.
3. 확장 프로그램 아이콘에서 버튼 문구가 `남은시간 …`으로 보이는지 확인한 뒤 **감시 시작**을 누르고 팝업을 닫습니다. 0초에 버튼이 활성화되면 자동으로 한 번 클릭합니다.
4. 사이트의 결과 화면에서 **버튼 바뀐 뒤** 기록을 확인합니다. 다시 시험하려면 사이트 페이지를 새로고침한 뒤 확장 프로그램에서 감시를 다시 시작합니다.

## 검증

Node.js 24 이상에서 `node --test tests/content.test.js tests/popup.test.js`를 실행합니다. `tests/mock-ticket.html`은 실제 서비스에 연결되지 않는 버튼 상태 확인용 모의 화면입니다. 확장 프로그램은 위 세 사이트에서만 시작되므로, 로컬 모의 동작의 자동 검증은 Node 테스트가 담당합니다.

확장 프로그램은 현재 열린 탭에만 접근하고, 최근 클릭 기록 한 건을 브라우저의 로컬 확장 프로그램 저장소에 보관합니다. 기록에는 탭 ID, 페이지 주소, 공연명, 버튼 문구와 두 시각이 들어갑니다. 확장 프로그램을 제거하면 이 기록도 삭제됩니다.

## 배포 ZIP 만들기

PowerShell에서 `./scripts/build-release.ps1`을 실행하면 `release/nol-ticket-watcher-v버전.zip`과 SHA-256 확인 파일이 생성됩니다. ZIP에는 확장 프로그램 실행 파일과 `INSTALL.md`만 들어갑니다.
